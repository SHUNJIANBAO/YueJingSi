# YueJingSi 多人联机 Demo

一个基于 Unity 的第一人称多人联机小游戏：多名玩家在同一场景中移动，共同推动场景里共享的物理球体。
项目同时提供两条联机路径——**局域网/本机 Host-Client 联机**（Mirror）与 **Steam 好友联机与邀请**（Mirror + FizzySteamworks）。

## 一、运行环境

| 项目 | 版本 / 说明 |
| --- | --- |

## 二、功能说明

**多人游戏**
房主以 Host 身份开启房间，其他玩家以 Client 身份加入。玩家位置与左右朝向实时同步，每个进程都能看到其他玩家在自己画面里移动。
同步策略按对象区分权威方：玩家移动采用**客户端权威**（本地即时计算位置后上传，服务器转发给其他人），保证操作零输入延迟、手感跟手。

**共享物理球体**
球体是全房共享的物理对象，所有玩家推的是同一个球。球体采用**服务端权威**：客户端只上报推力，由服务端逐物理帧合成合力驱动球体刚体。
因此多人同时推同一个球时会按合力滚动，不会出现多端争夺所有权导致的抖动或回弹。

**第一人称视角**
进入对局后相机挂在本地玩家身上。鼠标控制左右转向与抬低头（俯仰限制 ±60°），方向键或 WASD 负责平面移动。
左右朝向进入网络同步（其他人能看到你面朝哪边），抬低头只影响本人视角，不参与同步。

**中途加入同步**
本地 Mirror 路径下，房主已经开局后新加入的客户端会自动同步到场上已存在的玩家与已生成的球体，不需要等人齐才能开。
Steam 路径下为保证所有玩家从同一局开始，房主点开始游戏后房间即不再接纳新成员，房内成员统一进入对局。

**定时生成球体**
由主机驱动生成循环：每隔 15 秒在生成点生成一个可推动球体，场上同时最多存在 10 个，超出上限后销毁最早生成的那个。
新球一旦生成即对全部客户端同步，中途加入的玩家也能立刻看到场上已有的球。

**触碰球体 UI 提示**
玩家与球体发生接触时，界面上的状态文本由 `Untapped` 变为绿色的 `Tapped`；离开球体后恢复为白色的 `Untapped`。
状态以本地玩家的实际物理接触为准，多端各算各自的接触状态，互不干扰。

**主机退出提示**
房间阶段：房主点关闭房间或直接退出游戏时，其他成员会收到「房主已离开房间」的飘字提示，并自动退回房间列表界面。
对局阶段：房主进程结束导致连接断开时，客户端弹出断开面板，点击退出即可结束游戏。

**Steam 联机**
支持创建房间、房间列表、加入房间与密码房；建房时可设置房间名、密码与人数。
房间阶段（成员、房主、人数、开局标记）由 Steam 大厅承载，房主点开始游戏后才真正建立 Mirror 连接，成员读到开局标记后自动连入，所有人从同一时刻开局。

**Steam 邀请**
房主可通过 Steam 覆盖层邀请对话框直接邀请好友。被邀请方接受后会自动从房间列表界面进入该房间，随后房主点开始游戏即可一起进入对局。

## 三、技术选型说明

### 为什么选择 Mirror

- 测试需求的核心是 Host 与 Client 之间的联机，Mirror 的 `NetworkManager` / `NetworkIdentity` / `NetworkTransform` 组合开箱即用：Host 进程同时充当服务端与客户端，一个进程点一下就能起房，非常契合局域网联机场景。
- 同步粒度可控。本项目按对象分别选择权威方：玩家位置用客户端权威保证手感，共享球体用服务端权威保证一致性——这类「按对象挑权威」的灵活性正是 Mirror 的强项。
- 传输层与游戏逻辑解耦。Mirror 把数据传输抽成独立的 Transport，同一套游戏逻辑既能跑局域网传输，也能换成 Steam 传输，为加分题留好了接口。

### 为什么结合 FizzySteamworks

- 加分题要求 Steam 联机，而 Mirror 自带的传输层只解决「数据怎么传」，不提供 Steam 的大厅、房间列表与邀请等平台能力。
- FizzySteamworks 是 Mirror 的 Steam 传输层实现，把 Steam 的 P2P 连接与大厅接入 Mirror。替换传输层后，玩家生成、位置同步、RPC 等既有游戏逻辑完全不需要改动，只换传输通道即可。
- 房间阶段的状态直接挂在 Steam 大厅的原生数据上（成员、房主、人数、开局标记），由 Steam 回调驱动刷新，不必为大厅阶段另写一套自定义同步协议；只有真正开局时才启动 Mirror 会话，职责边界清晰。
- 邀请使用 Steam 官方覆盖层邀请对话框，接受邀请的回调会直接带回房间 ID，省去了自建好友列表与邀请确认流程。

## 四、测试方法

### 4.1 本地（localhost）联机测试

用 `Build/YueJingSi.exe` 多开进程即可，不依赖 Steam。

| 步骤 | 操作 | 预期现象 |
| --- | --- | --- |
| 1 | 多次双击 `Build/YueJingSi.exe`，启动多个游戏进程 | 每个进程显示启动画面与主界面，主界面有 Steam / LocalHost / Exit Game 三个按钮 |
| 2 | 选一个进程当主机：点 LocalHost，再点 Host | 黑屏过渡后进入对局场景，视角为第一人称；球体每 15 秒在生成点出现一个，场上最多 10 个 |
| 3 | 其余进程点 LocalHost，再点 Client | 黑屏过渡后进入同一局；能看到主机玩家与场上已经生成的球体（中途加入同步） |
| 4 | 各进程用方向键或 WASD 移动、鼠标转向 | 每个进程都能看到其他玩家的移动与朝向变化，球体位置在各端一致 |
| 5 | 走到球旁持续推动，并让两三个玩家一起推同一个球 | 球被推动；界面文字由 `Untapped` 变为绿色 `Tapped`，离开后恢复；多人同时推时球朝合力方向滚动，各端表现一致 |
| 6 | 关闭主机进程 | 其余进程连接断开并弹出断开面板，点退出结束游戏 |
| 7 | 在本地面板点 Back | 黑屏过渡后卸载联机场景，回到主界面 |

### 4.2 Steam 联机测试

**前置条件**

- 把整个 `Build` 文件夹移动到桌面（Steam 添加非 Steam 游戏后路径需保持稳定，`steam_appid.txt` 必须与 exe 同目录）。
- 准备两台机器（或两个 Steam 客户端环境），分别登录**不同的 Steam 账号**，否则房间列表与好友邀请看不到对方。
- 在 Steam 左下角「添加游戏」→「添加非 Steam 游戏」，把 `YueJingSi.exe` 添加为启动程序，之后从 Steam 库启动游戏（以 Steam 游戏方式启动才能正常调起覆盖层）。

| 步骤 | 操作 | 预期现象 |
| --- | --- | --- |
| 1 | 房主从 Steam 库启动游戏，主界面点 Steam | 黑屏过渡后进入房间列表界面 |
| 2 | 房主点右上角 Create | 进入建房界面，可填写房间名与密码，确认后房间创建成功并进入房间界面（start / leave / close / yaoqing 四个操作） |
| 3 | 另一账号启动游戏，主界面点 Steam，进入房间大厅 | 房间列表里能看到房主刚创建的房间及人数信息 |
| 4 | 点该房间条目（有密码则先输入密码） | 成功进入房间，双方成员列表同步显示彼此，房主一侧显示 start 按钮 |
| 5 | 房主点 yaoqing（邀请好友） | 弹出 Steam 覆盖层邀请对话框，选择好友发送邀请 |
| 6 | 被邀请方在 Steam 覆盖层接受邀请 | 自动从房间列表界面进入房间，双方成员列表同步更新 |
| 7 | 房主点 start | 房间标记为已开局并停止接纳新成员，双方黑屏过渡后同时进入对局场景，可互相看到并推动球体 |
| 8 | 房主点 close 关闭房间（或直接退出游戏） | 成员收到房主已离开房间的提示，自动退回房间列表界面 |
| 9 | 对局过程中关闭房主进程 | 成员端连接断开并弹出断开面板 |
